# HU-03 — User Logout

## Implementation and decisions

Added `POST /api/auth/logout` accepting a JSON `refreshToken` string. The controller reuses HU-02's SHA-256 hashing helper and performs a conditional Prisma `updateMany` on the matching unrevoked session, setting `revokedAt`. This single database operation avoids a separate lookup and naturally provides idempotent behavior: unknown and already revoked tokens also return HTTP 204 with no body. Repeated logout preserves the original revocation timestamp.

Missing, empty, or non-string token fields return 400. Unexpected database failures return a generic 500 response. Responses and application logs do not expose tokens or hashes. Existing login and refresh logic remains unchanged; no new library, migration, or architectural layer was needed.

## Verification

Executed `npm test` against the configured local PostgreSQL database. The first run found an incorrect test expectation for a JSON `null` body: Express rejects it with 400 before the controller. Corrected the expectation without changing application behavior and reran the suite. All 16 reported tests passed, including the existing login, refresh rotation, seed, and health checks.

Logout checks verify login followed by logout and a rejected refresh (401); empty 204 responses for initial, repeated, and unknown-token logout; an unchanged revocation timestamp after repeated logout; a second session belonging to the same user remaining usable; and 400 responses for missing and invalid token fields. The access JWT signature remains valid after logout, matching the documented limitation. Tests reuse existing ports and remove their own fixture users and sessions. No manual verification was performed.

## Limitations

Logout revokes only the supplied refresh session. Previously issued access JWTs remain valid until their existing 15-minute expiration. If a token has already rotated, its replacement represents the current session and must be supplied to log it out. Frontend integration, access-token blacklisting, logout on all devices, and automatic session cleanup are outside scope. No configuration or installation changes are required.
