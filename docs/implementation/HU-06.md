# HU-06 — View Own Profile

## Implementation

- `GET /api/users/me` reuses `authenticate` and allows active ADMIN, CLIENT, and TECHNICIAN users.
- The controller queries Prisma using `req.user.id` and returns only `id`, `name`, `email`, and `role`. Query parameters cannot select another account.
- Missing, invalid, expired, or incorrectly signed access tokens and missing or inactive accounts return `401` using the existing authentication response. Unexpected database errors return a generic `500`.

## Decisions and important files

- `backend/src/controllers/user.controller.js`: `getOwnProfile` retrieves current database values with an explicit field selection, checks active status, and builds the four-field response without exposing hashes or sessions.
- `backend/src/routes/user.routes.js`: registers `/me` before dynamic user routes with authentication only; administrator authorization is not required.
- `backend/tests/users.test.js`: extends existing integration fixtures to verify all three roles, exact response fields, updated database values with an existing token, ignored account query input, invalid authentication, and rejection after deactivation.
- No dependencies, schema changes, or additional layers were needed. The existing authentication middleware remains unchanged.

## Limitations

- The endpoint performs a profile lookup in addition to the existing authentication lookup. Integration tests require the configured PostgreSQL database and seeded administrator.
- Profile editing, password changes, and Angular integration are outside this task's scope.
- Configuration and execution instructions did not change, so no README changes were needed.
