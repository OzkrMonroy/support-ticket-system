# HU-10 — Soft Delete Support Tickets

Status: Completed; tested and explicitly approved by the user.

## Implementation and decisions

- Added nullable Ticket.deletedAt through additive migration `20261024000000_soft_delete_tickets`. Existing records remain intact with null deletedAt; no reset or physical application deletion is used.
- Added authenticated DELETE /api/tickets/:id using the existing UUID validator and current database account/role checks. CLIENT may delete own OPEN tickets, ADMIN may delete any non-deleted ticket regardless of status, and TECHNICIAN may not delete.
- Visibility is checked before permissions: missing, invisible, and already-deleted tickets return the same 404. Forbidden visible requests return 403 without modifying records. Successful deletion returns an empty 204, sets deletedAt, preserves status and other business fields, and lets Prisma update updatedAt.
- Conditional updateMany rechecks non-deletion, ownership/visibility, and the CLIENT OPEN requirement at write time. A failed conditional write rechecks visibility to distinguish 403 from 404.
- The shared Prisma visibility filter now excludes deleted tickets from lists, details, updates, and deletion. Existing ordering and HU-07 through HU-09 rules remain intact. Newly created tickets return deletedAt: null.
- No dependencies, generic deletion framework, or new architectural layers were added.
