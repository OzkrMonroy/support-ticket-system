# HU-07 — Create Support Tickets

Status: Completed; tested and explicitly approved by the user.

## Implementation and decisions

- Added Ticket with UUID identity, priority/status enums, required creator, optional assignee, and timestamps. Named User relations distinguish creation and assignment. The additive migration preserves existing records.
- Added POST /api/tickets using the existing route/controller/direct-Prisma pattern, without new dependencies or layers.
- Reused authentication and current-account checks. CLIENT and ADMIN may create tickets; TECHNICIAN receives 403 before body validation.
- Strict Zod validation accepts only title, description, and priority. Text is trimmed; limits are 200 and 5000 characters. Creator is taken from req.user; database defaults provide OPEN status and null assignment. Responses contain only persisted ticket scalar fields.

## Verification performed

- prisma format, prisma generate, and prisma validate succeeded.
- Generated SQL with prisma migrate diff against the previous schema and inspected it: only ticket enums, table, and foreign keys are added.
- prisma migrate deploy applied the migration to local PostgreSQL without a reset; prisma migrate status reports up to date.
- Initial sandbox test run could not access PostgreSQL/local HTTP sockets. Reran with the required access.
- First accessible run exposed a test expectation mismatch for JSON null, which Express rejects before Zod. Adjusted the test to the existing behavior.
- Final npm test: 31 passed, 0 failed. New integration coverage verifies both allowed roles and all priorities, persisted fields/defaults/timestamps, authentication, inactive/missing accounts, current database roles, role checks before validation, invalid types/lengths/enums, and rejection of server-owned/unknown fields without persistence. Fixtures are removed only by this test's creator IDs.

## Limitations

- Shared validation reports field paths only: strict unknown-key failures return the established message/errors envelope with an empty errors object. JSON null follows the existing Invalid JSON body response.
- Ticket listing, details, updates, deletion, status transitions, assignment jobs, notifications, and frontend are outside HU-07.
- HU-07 is user-approved and marked Completed in the roadmap.
