# HU-08 — List Support Tickets and View Ticket Details

Status: Completed; tested and explicitly approved by the user.

## Implementation and decisions

- Added authenticated GET /api/tickets and GET /api/tickets/:id using existing routes/controllers and direct Prisma queries.
- A shared visibility filter restricts both database queries: ADMIN sees all, CLIENT sees created tickets, TECHNICIAN sees assigned tickets only. Authentication supplies the current database role and rejects missing/inactive accounts.
- Lists return an array ordered by createdAt descending, then id descending. Detail returns the same 404 message for missing and inaccessible tickets.
- Reused Zod parameter validation and the existing UUID convention after authentication; malformed IDs return the established 400 message/errors envelope.
- Both reads return persisted ticket fields and createdBy/assignedTo relations with only id, name, email, and role. Unassigned tickets have assignedTo: null. POST behavior is unchanged.
- Existing models and relations suffice; no migrations, dependencies, or extra architectural layers were added.
