# HU-03 — User Logout

## User story

As an authenticated user, I want to log out so that my current refresh token can no longer be used to renew my session.

## Objective

Implement a simple logout endpoint using the existing `RefreshSession` model and authentication conventions established in HU-01 and HU-02.

## Scope

1. Add `POST /api/auth/logout` to the existing authentication routes and controller.
2. Accept a `refreshToken` in the JSON request body.
3. Find the corresponding refresh session using the same token-hashing mechanism implemented in HU-02.
4. Revoke the matching active session by setting its existing `revokedAt` field.
5. Return `204 No Content` when logout succeeds.
6. Treat an already revoked or unknown refresh token as a completed logout and return `204 No Content` (idempotent behavior). Return `400 Bad Request` if `refreshToken` is missing or is not a string.
7. Keep all existing login and refresh behavior unchanged.

## Acceptance criteria

- A refresh token that previously worked cannot be used with `POST /api/auth/refresh` after logout.
- Logout returns HTTP `204` with no response body for a valid, already revoked, or unknown refresh token.
- A missing or non-string `refreshToken` returns HTTP `400`.
- Logging out one refresh session does not revoke other sessions belonging to the same user.
- No refresh token or token hash is exposed in responses or logs.
- Existing login and refresh tests continue to pass.

## Minimal tests

- Login, logout with the issued refresh token, then attempt refresh: refresh must fail with `401`.
- Logout twice with the same token: both logout requests return `204`.
- Missing refresh token returns `400`.
- Run the existing automated test suite and report results.

## Constraints

- Follow `AGENTS.md` and the existing project structure.
- Use JavaScript ESM, Express, and Prisma; do not introduce additional libraries or architectural layers.
- Reuse existing token utilities and the `RefreshSession` model. Do not add a database migration unless the existing schema genuinely requires it.
- Do not implement frontend integration, access-token blacklisting, logout-all-devices, or automatic session cleanup.
- An already issued access token may remain valid until it expires; logout only prevents further refreshes. Document this limitation.
- Do not change unrelated application code.
