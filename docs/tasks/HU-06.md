# HU-06 — View Own Profile

## User Story

As an authenticated user (ADMIN, CLIENT, or TECHNICIAN), I want to view my own profile information so that I can identify the account currently in use.

## Scope

Implement a single protected endpoint:

`GET /api/users/me`

Reuse the existing JWT authentication middleware and Prisma `User` model. Follow `AGENTS.md` and existing backend conventions. Keep the implementation minimal.

## Requirements

1. Require a valid access token in the `Authorization: Bearer <accessToken>` header.
2. Return the authenticated user's current information from the database, not from untrusted request input.
3. Allow all three roles: `ADMIN`, `CLIENT`, and `TECHNICIAN`.
4. Reject unauthenticated requests and inactive users with `401 Unauthorized`, using the project's existing authentication conventions.
5. Return `200 OK` with only these fields:

```json
{
  "id": "user-uuid",
  "name": "Example User",
  "email": "user@example.com",
  "role": "CLIENT"
}
```

6. Never expose `passwordHash`, refresh tokens, or other sensitive fields.
7. Ensure `/api/users/me` is not incorrectly interpreted as an `:id` route if dynamic user routes exist.

## Out of Scope

- Editing profile information
- Changing passwords
- Listing other users
- New authentication mechanisms, database tables, or dependencies
- Angular integration

## Acceptance Criteria

- A valid access token for an active user returns `200` and the expected profile fields.
- ADMIN, CLIENT, and TECHNICIAN can access their own profiles.
- Missing, invalid, or expired access tokens return `401`.
- A deactivated user cannot access the endpoint with a previously issued token.
- The response never includes `passwordHash`.
- Existing authentication and user-management endpoints continue to work.
